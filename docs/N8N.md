# n8n workflows

> **Verification status:** verified in real n8n 2.43.4 under Docker Compose (2026-10-26): all three workflows imported and active, unauthenticated webhook calls return 401, and one repository analysis, documentation run and Q&A request completed through them. The AI branches were not exercised (no LLM key). See `evaluation/EVALUATION_AND_RESULTS.md`.

Three workflows, generated by `automation/n8n/build_workflows.py` and committed as JSON:
`raven_repository_analysis.json`, `raven_documentation_generation.json`, `raven_codebase_qa.json`. They contain **no secrets and no credentials objects**.

## Required n8n environment
| Variable | Purpose |
|---|---|
| `RAVEN_API_BASE_URL` | e.g. `http://api:8000` — where n8n reaches the API (internal network) |
| `INTERNAL_SERVICE_SECRET` | sent as `X-Internal-Secret` to the API (same value as the API's) |
| `N8N_WEBHOOK_SECRET` | expected in `X-Raven-Webhook-Secret` on inbound webhooks (same value as the API's) |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` | lets workflow expressions read the variables above (n8n 2.x blocks this by default) |
| `N8N_SELF_URL` | how workflow 1 reaches workflow 2's webhook (default `http://localhost:5678`) |
| `RAVEN_MAX_ANALYSIS_SECONDS`, `RAVEN_MAX_DOCS_SECONDS` | poll time budgets (defaults 600 / 900) |
| `N8N_ENCRYPTION_KEY` | n8n's own at-rest encryption key |

Docker Compose sets all of these and **imports and activates the workflows automatically** on container start (`infra/n8n-entrypoint.sh`).

## Manual import (no Compose)
1. Start n8n with the environment above.
2. CLI: `n8n import:workflow --separate --input=automation/n8n/` then activate each workflow (`n8n publish:workflow --id=<id>` on n8n 2.x), **or** in the editor: *Workflows → Import from file* for each JSON, open it, and toggle **Active**.
3. Workflow IDs are fixed (`raven_repository_analysis`, `raven_documentation_generation`, `raven_codebase_qa`); re-importing updates in place.
4. Confirm: `curl -s -o /dev/null -w "%{http_code}\n" -X POST http://<n8n>:5678/webhook/raven-analysis` must return **401** (active + secret required). `404` means the workflow is not active.

## Behaviour
* **Auth**: webhooks compare the secret header in constant time and return 401 otherwise; ids must be UUIDs.
* **Retries**: dispatch retried up to 4× with backoff; polling tolerates up to 8 consecutive API errors; when the backend reports `RETRYING` the workflow waits the backend-computed jittered delay and re-dispatches. Retry limits live in the backend (`MAX_STAGE_ATTEMPTS`).
* **Timeouts**: poll loops are bounded; on expiry the workflow calls `/fail` with `WORKFLOW_TIMEOUT`.
* **Failure**: every error path ends in `/fail` (restricted code set; n8n cannot inject free-text messages).
* **Idempotency**: all callbacks carry `executionId`-derived idempotency keys.
* **Observability**: each run is recorded in `workflow_runs` with the n8n execution id; shown in the analysis timeline API.
* **If n8n is down**: submissions are accepted and stay `QUEUED`; the worker re-triggers every ~90 s up to `TRIGGER_MAX_ATTEMPTS`, then marks the job `FAILED` (`ORCHESTRATOR_UNAVAILABLE`, user-retryable). Q&A returns a retryable 503.
